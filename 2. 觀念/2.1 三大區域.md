## 2.1 三大區域
### 工作目錄(Working directory), 暫存區域(Staging area)  和儲存庫 (Repository)

> 在學指令之前, 先搞懂這三個區塊, 後面 add / commit / checkout 才不會越用越混亂 <br>
> Git 跟很多舊版控系統不太一樣: 它不是只記「檔案改了什麼差異」, 而是把每次提交看成專案的一張**快照(Snapshot)** <br>
> 每次 commit, Git 會記下當下所有檔案的樣子; 沒變的檔案就不重複存, 直接指向上一次的版本, 所以既像備份, 也像版控

<br><br>


## 1. 工作目錄 (Working Directory)

> 就是你在電腦上**看得到、改得到**的專案資料夾 <br>
> 你在這裡建立、修改、刪除檔案, 但這些變更還沒被 Git 正式記錄 <br>
> 工作目錄顯示的是「目前這個版本」被取出來給你編輯的樣子

# 平常寫程式、改檔案的地方
# 檔案在這裡被改動, 狀態是 modified（見 2.2 檔案狀態）
<br><br>


## 2. 暫存區 (Staging Area / Index)

> 英文也叫 stage 或 index, 資料通常存在 `.git/index` 裡, 所以有時也叫**索引** <br>
> 暫存區是一個**中間站**: 你決定「這次 commit 要包含哪些變更」 <br>
> 可以只 `git add` 部分檔案, 不必一次把整個專案全部提交

> **為什麼需要暫存區?** <br>
> 假設同時改了 a.html、b.html(購物車) 和 c.html(首頁), 這是兩件不同的事 <br>
> Git 是以「**這次做了什麼**」為單位記錄, 不建議把不相關的修改塞進同一個 commit <br>
> 可以先 add a、b 做一次 commit, 再 add c 做另一次 commit, 之後回溯才看得懂

# working directory -> staging area 靠 git add
# 決定下一次 commit 要打包哪些變更
<br><br>


## 3. 儲存庫 (Repository)

> 專案裡有一個隱藏的 `.git` 資料夾, **它不算工作目錄**, 而是 Git 的儲存庫 <br>
> 裡面有完整的 commit 歷史、分支、標籤等資訊 <br>
> `git commit` 之後, 暫存區的快照會被寫進儲存庫, 成為一個永久的版本紀錄 <br>
> 儲存庫又分**本地**與**遠端**; 遠端與協作見 2.4、GitHub 見 2.5
