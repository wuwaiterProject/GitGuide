# 2.4 個人 / 團體協作

> Git 本質上是**分散式**版控: 每個人電腦上都有一份完整的本地儲存庫 <br>
> 個人用和團隊用, 差別在於**要不要跟別人同步**, 以及**同步時要注意什麼**

<br><br>


## 本地 vs 遠端

> **本地儲存庫** — 你電腦上的 `.git`, commit 先存在這裡 <br>
> **遠端儲存庫** — 放在 GitHub 等伺服器上的副本, 給備份與協作用 <br>
> `git remote` 把本地和遠端連起來, 慣用名稱是 `origin`

<br><br>


## 個人開發

> 一個人寫專案時, 可以只在本地 add → commit, 不一定要連遠端 <br>
> 但建議還是推到 GitHub 當備份, 換電腦或硬碟壞了才救得回來 <br>

```
git init → 改檔案 → git add → git commit → (git remote add) → git push
```

> 個人流程比較自由: <br>
> - 可以直接在 main 上 commit（小專案、自己玩沒問題）<br>
> - 也可以開分支開發, merge 回 main 再 push <br>
> - push 前自己決定要不要先 merge, 沒有別人在等你

# 本地 commit 就是自己的版本紀錄
# push 是備份到遠端, 可選但建議做
<br><br>


## 團體協作

> 多人共用同一個遠端 repo 時, 規則變嚴格: <br>
> - **開始工作前先 pull**, 拿到別人最新的 commit <br>
> - **功能用分支開發**, 不要大家都直接改 main <br>
> - **改完再 push**, 讓團隊看到你的手稿 <br>
> - **push 前先 fetch/pull**, 確認遠端沒有你不知道的變更

```
git clone → git pull → 開分支 → 改檔案 → add → commit
         → pull(或 fetch + merge) → merge 回 main → git push
```

> **git fetch** 只下載遠端更新, 不動你的工作目錄 <br>
> **git pull** = fetch + merge, 會把遠端變更合併進你目前的分支 <br>
> `git status` 比的是本地分支狀態; 若沒先 fetch, 不一定反映遠端最新情況

<br><br>


## 個人 vs 團體 — 差在哪

| | 個人 | 團體 |
|---|---|---|
| 衝突風險 | 低, 多半只有自己改 | 高, 可能改同一檔案 |
| push 時機 | 自己決定 | 需配合團隊, 避免覆蓋別人 |
| 分支 | 可選 | 建議功能分支 |
| pull 習慣 | 可選 | 工作前必做 |
| reset / 改歷史 | 影響自己 | 已 push 的紀錄會影響他人 |

<br><br>


## 協作時要特別小心

> 已經 **push 給別人** 的 commit, 不要隨便 `reset --hard` 或改寫歷史 <br>
> 別人電腦上可能已經基於那個版本繼續開發, 你這邊抹掉會造成混亂 <br>
> 若兩人改到同一處, merge 時會產生 **Conflict**, 需手動選要留哪段程式再 commit

# 個人: 自由度高, 遠端當備份
# 團體: 先 pull、用分支、謹慎 push
# GitHub 上的實際操作見 2.5
