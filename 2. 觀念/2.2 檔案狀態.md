# 2.2 檔案狀態

> 每個被 Git 管理的檔案, 大致會落在以下狀態之一 <br>
> 搞懂狀態, 才看得懂 `git status` 在說什麼

<br><br>


## 三種主要狀態

> **已修改(modified)** — 工作目錄裡有改動, 但還沒進暫存區 <br>
> **已預存(staged)** — 已經 `git add`, 準備進下一次 commit <br>
> **已提交(committed)** — 已經 `git commit`, 安全存在本地 `.git` 裡 <br>
> 這三種狀態, 剛好對應 2.1 的三大區域

<br><br>


## 尚未追蹤 (untracked)

> 專案裡有新檔案, 但 Git 還沒開始管理它 <br>
> `git status` 會顯示 untracked files <br>
> 第一次 `git add` 之後, 才會變成 tracked, 進入上述三種狀態的循環

# untracked -> tracked 靠 git add
<br><br>


## 狀態轉換一覽

```
untracked  --git add-->  staged  --git commit-->  committed
                            ↑
modified  --git add--------┘
   ↑
   └── 在工作目錄修改已追蹤的檔案
```

> committed 的檔案若再次修改, 又會回到 modified <br>
> 可以反覆 add → commit, 累積版本歷史

<br><br>


# 補充觀念

> **Git 記的是變更, 不是「資料夾本身」** <br>
> Git 詳細記錄檔案內容多了什麼、少了什麼; 空資料夾通常不在 Git 的管轄範圍內

> **Git 幾乎只會增加資料** <br>
> 一旦 commit 進儲存庫, 資料很難真正消失; 很多「刪除」只是讓某個版本不再出現在目前分支上 <br>
> 這也是為什麼可以大膽嘗試, 但 push 給別人之後就要更小心（見 2.4）

> **大部份操作在本地端就能完成** <br>
> commit、看歷史、比對差異都不需要網路; 只有跟遠端同步時才需要連線
