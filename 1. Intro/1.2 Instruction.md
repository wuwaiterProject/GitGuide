## git init
```git init```
> 把當前資料夾初始化為一個全新的 git 儲存庫(repo)
> git init的當下, 只有本地端的 git管控
> git init之後會產生 .git資料夾 裡面是 git管控的全部資訊
> 如果不小心把 .git資料夾刪除了, 那全部的git紀錄就都不見了
> 這邊還有一個小地方, 在git init的當下  repo中是沒有任何的分支, 也沒有main/master

#一個全新的專案
#一個既有的專案加入git管控
<br><br>


## git clone
```
git clone [url]
```
> 從遠端儲存庫複製一份到本地端的當前資料夾

#取得遠端repo
#從 個人/團隊/公開的repo, 複製到本地端
#github上 fork動作的本地化
<br><br>


## git add
``` 
git add [file name]
git add [folder]
```
> 在 git init之後, 此時專案中還沒有任何檔案, 需要使用 git add將檔案加入(staged)
> git add .  代表增加全部的檔案, 除了init以外  不建議使用 git add .
> 也可以直接 git add 整個資料夾

#untracked -> tracked
#working directory -> staging area
<br><br>


## git commit
```
git commit -m "message"
```
> git add 之後, 檔案在暫存區(staged), commit 會把這批變更寫入本地儲存庫, 形成一個版本快照
> -m 可以直接在指令列寫 commit 訊息, 不加 -m 則會開啟編輯器
> commit 只影響本地端, 不會自動上傳到遠端

#staged -> committed（暫存區 -> 本地儲存庫）
#在本地端存一個可回溯的版本
#一個branch 可以commit很多次
#每次的commit都會產生一個 Hash key
#commit 的 hash 和 branch 的 tag 不同, commit 有包含檔案內容
<br><br>


## git remote
```
git remote -v
git remote add origin [url]
```
> git init 只有本地端, 要與 GitHub 等遠端連線, 需要先設定 remote <br>
> origin 是慣用的遠端名稱(可自訂, 但多數教學用 origin) <br>
> git remote -v 可以查看目前綁定的遠端 URL

#git init 之後, 把本地 repo 連到 GitHub
#確認/設定 push/pull 指向哪個遠端
<br><br>


## git push
```
git push
git push origin [branch]
git push -u origin [branch]
```
> 把本地已 commit 的紀錄推送到遠端
> 需要先設定 remote, 且遠端通常要有對應的分支
> 第一次 push 新分支時, 建議用 -u 建立追蹤關係, 之後就可以只用 git push

#本地 commit 備份/同步到遠端
#團隊協作: 讓別人看到你的變更
<br><br>


## git fetch
```
git fetch
git fetch origin
```
> 從遠端下載最新的 commit 與分支資訊到本地, 但不會自動合併到目前工作目錄
> 適合先看遠端有什麼變更, 再決定要不要 merge
> 與 pull 的差別: fetch 只抓資料, pull = fetch + merge
> git status 比較的是當下分支和本地紀錄的差異, 無法確定 remote 上是否也已經修改

#查看遠端更新
#不會改動本地檔案
#pull 之前先了解遠端狀態, git status 才會準確
<br><br>


## git pull
```
git pull
git pull origin [branch]
```
> 從遠端拉取更新, 並自動合併到目前分支
> 概念上等同 git fetch + git merge
> 多人協作時, 開始工作前常先 pull, 減少衝突

#取得遠端最新版本到本地
#團隊協作: 別人的 commit 同步到自己電腦
<br><br>


## git branch
```
git branch [branch name]
git branch --list
```
> git branch [branch name] 是建立一個新的分支
> 分支是同一 repo 內的平行開發線
> 分支只是一個 tag, 並不會變更任何檔案
> git branch --list 列出本地分支, * 代表目前所在的分支 (不加 --list 也可以, 但建議加上)

```
git branch -d [branch name]
git branch -D [branch name]
```
> -d/-D 都是刪除, -D 是強制刪除
> 如果還沒有 commit 的分支, -d 會提示還沒有 commit 不可以刪除
> 刪除分支, 保持 branch 的乾淨是常見的做法

#開功能分支, 不直接動 main
#查看目前有哪些分支
#分支只是一個 tag, 不包含任何檔案
<br><br>


## git checkout
> checkout 有兩種常見用途: 切換分支、還原檔案

```
git checkout [branch-name]
git checkout -b [branch-name]
```
> git checkout [branch-name] 切換到指定分支, 是早期常用的分支切換指令
> git checkout -b [name] 等同建立新分支並立刻切過去(= git branch [name] + git checkout [name])

```
git checkout -- [file name]
git checkout HEAD -- [file name]
```
> git checkout -- [file name] 放棄工作目錄中對該檔案的修改, 還原到暫存區或上一次 commit 的內容
> git checkout HEAD -- [file name] 明確從上一次 commit 還原該檔案, 連暫存區的變更也一併丟棄

```
git switch [branch-name]
git restore [file name]
```
> 新版 git 建議用 git switch 切分支、git restore 還原檔案, checkout 功能較多也較容易混淆

#切換分支
#建立分支並立刻切換(-b)
#還原/放棄對某個檔案的本地修改
#git checkout 約等於 git switch + git restore
<br><br>


## git merge
```
git merge [branch-name]
```
> 把指定分支的變更合併進目前分支
> 常見流程: 在功能分支開發完 -> 切回 main -> git merge feature-xxx
> 若兩邊改到同一處, 可能產生衝突, 需手動解決後再 commit

#功能分支開發完成, 併回 main
#pull 的本質之一: 把遠端變更 merge 進本地
#個人開發的時候, 我會先 merge 到 main 之後再 push 到 remote
<br><br>
